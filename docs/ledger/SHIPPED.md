(3) AI CLARIFYING QUESTIONS on the product form: a new `clarify` action on `product-request-action` asks Claude for the 2-3 things a developer would otherwise have to come back and ask, rendered inline as optional one-line fields and folded into the filed description as a Q/A block. Runs **alongside** the client-impact classifier in one `Promise.all`, so a bug costs ONE pause and one spinner rather than two; a request that was already specific gets no questions and no extra click. Unlike `classify_bug` this does NOT proxy to Helm — client-impact judgement is grounded in the Medcurity codebase, but "what did you expect instead?" needs only the requester's own words, so it calls Anthropic directly (saving a hop on a path a person is waiting on) and needs no new secret: `ANTHROPIC_API_KEY` is already present for Meddy/ask-ai. It ALWAYS returns 200 — questions are additive, so a slow/rate-limited/unparseable response yields an empty list and a form that submits normally, and failure is deliberately indistinguishable from "nothing was unclear". Answers are folded in at submit time rather than written back into description state, because every edit to that field re-runs `invalidateVerdict` and would have thrown away the client-impact check the moment the answers landed. Questions are NOT invalidated on edit, on purpose: the common edit is answering them, and yanking half-typed answers away is worse than a question that's since been addressed.
